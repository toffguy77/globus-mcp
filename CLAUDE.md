# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Язык

Код, докстринги, комментарии и документация — на русском. Докстринги инструментов —
это описания, которые видит LLM-клиент; пиши их так же (по-русски, с указанием
формата аргументов и откуда их взять).

## Команды

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

pytest                                   # 76 тестов, все офлайн
pytest tests/test_tools.py -k cart_add   # один тест
ruff check .
globus-mcp                               # stdio-сервер (сам по себе ничего не печатает)
```

Инструменты — обычные функции модуля, декоратор `@mcp.tool()` их не оборачивает,
поэтому любой вызывается напрямую из Python для отладки без запуска сервера:

```python
from globus_mcp.server import search_products
print(search_products("молоко", per_page=3))
```

Состояние сессии — `~/.globus-mcp/state.json`, переопределяется переменной
`GLOBUS_MCP_HOME`. Удали файл, чтобы получить новый анонимный `app_id`.

## Процесс

`main` защищена: прямой push запрещён, включая владельца. Любое изменение —
через pull request с зелёным CI (pytest на 3.10–3.13, ruff, сборка пакета).
Апрувы не требуются. Подробности — `CONTRIBUTING.md`.

## Архитектура

Два модуля:

* `globus_mcp/client.py` — `GlobusClient`: транспорт, состояние, распаковка ответов.
  Знает только про HTTP; никакой логики форматирования.
* `globus_mcp/server.py` — 22 MCP-инструмента поверх клиента плюс нормализация.

Ключевые особенности, которые надо держать в голове при правках:

**Клиент ленивый.** `gc()` — синглтон, создаётся при первом обращении, а не на
импорте: импорт пакета не должен писать в `$HOME` и открывать соединение. Внутри
инструментов всегда `gc().get(...)`, не `gc.get(...)`.

**Два источника данных.** Основной — BFF `https://digitalone.globus.ru/d1-front-bff/api-web/v1`
(`gc().get/post/patch`). Детальная карточка товара в BFF не отдаётся и берётся из SSR
Next.js: `gc().next_data("/products/<slug>")` → `query_data(json, "product-detail")`.
`buildId` кешируется на 15 минут и перечитывается при 404 (деплой сайта). Понадобятся
ещё SSR-данные — тот же путь, а не новый эндпоинт.

**Сессия привязана к `X-App-Id`.** Заголовок обязателен, содержит uuid устройства из
state-файла. `Authorization: Bearer <JWT>` опционален: анонимно работают поиск,
каталог, акции **и корзина**. Авторизация нужна только для `checkout_info`,
`already_bought_tape` и адресов доставки.

**Контекст получения меняет цены и наличие.** `purchase_method` (1 — гипермаркет
/`store_id`, 2 — доставка/`address_id`, 3 — ПВЗ/`pvz_id`) ставится `PATCH context`
с телом `{"context": {...}}`. При расхождениях в ценах сначала смотри `globus_status()`.

**Все цены в API — копейки.** Каждое значение проходит через `rub()` перед отдачей
наружу. Новые поля с ценами не забывать оборачивать.

**Единый формат товара.** `brief(p)` — общее компактное представление для поиска,
каталога, корзины и карточки; выкидывает пустые ключи. Меняешь вид товара — меняй
`brief`, а не отдельные инструменты.

**Распаковка ответов.** `GlobusClient._unwrap` разворачивает конверт `{"data": …}`
и превращает непустой `errors` в `GlobusError` даже при HTTP 200. Инструменты обычно
дают ошибке всплыть; ловят её только там, где деградация осмысленна
(`globus_status`, `cart_add`).

**Совместимость с mcp 1.x и 2.x** — импорт `FastMCP`/`MCPServer` в начале `server.py`
выбирается по `ModuleNotFoundError`. В `.venv` стоит mcp 2.1.1, то есть реально
работает ветка `MCPServer`; ветку с `FastMCP` не ломать.

**ПДн наружу не вываливать.** `checkout_info()` отдаёт структурированную выжимку,
а не сырой ответ: в нём ФИО, телефон и адреса. Тот же принцип для новых инструментов.

## Тесты

Ни один тест не ходит в сеть и не трогает `~/.globus-mcp` — это свойство надо
сохранять. Механика в `tests/conftest.py`:

* `isolated_state` (autouse) уводит `GLOBUS_MCP_HOME` во временный каталог;
* `no_real_client` (autouse) сбрасывает синглтон между тестами;
* `fake_client` + `recorder` подменяют транспорт на `httpx.MockTransport`;
  `recorder.route(method, url, payload)` задаёт ответ, `recorder.body(i)` достаёт
  тело i-го отправленного запроса — так проверяется форма исходящих запросов.

Слаги в URL для SSR-тестов бери ASCII: кириллица percent-кодируется, и роут
не совпадёт.

## Особенности API

Полностью — `docs/API.md`. Коротко о том, на чём легко споткнуться:

* `catalog:product-list` — двоеточие после `catalog`, не слеш. Тело требует и `url`
  (со слешами по краям), и `category_id`.
* Фильтры каталога — строки `"<id фильтра>:<id значения>"`, у флаговых значение
  буквально `"да"`. Строки собирает `category_filters` — вручную не конструировать.
* `per_page` до 100 работает.
* Второй шаг SMS-логина (`{phone, code}`) **угадан и не проверен на живом входе**.
  Обходной путь — `auth_set_token` с JWT из браузера, токен живёт час.
* Сайт закрыт для зарубежных IP — без российского адреса живой API не проверить.

## Границы

Оформление заказа и оплата не реализованы намеренно — не добавлять. Обход блокировок
и антибот-защиты — тоже. Рецептов у ГЛОБУСа нет вовсе; ближайшее —
`recommendations(block="combo_tape")` и `promotions()`. Избранное и история заказов —
эндпоинты не найдены.
