# Политика безопасности

## Поддерживаемые версии

Проект развивается в одной ветке. Исправления выходят в `main` и в ближайшем релизе.

| Версия | Поддержка |
|---|---|
| 0.1.x | да |

## Как сообщить об уязвимости

**Не заводите публичный issue.**

Используйте приватный канал GitHub —
[Security → Report a vulnerability](https://github.com/toffguy77/globus-mcp/security/advisories/new)
— или напишите на toffguy77@gmail.com.

Опишите: что не так, как воспроизвести, чем это грозит. Ответ — в течение 7 дней.
Исправление согласуем перед публикацией.

## Что считается уязвимостью проекта

* утечка токена или состояния сессии за пределы `~/.globus-mcp/state.json`;
* небезопасные права на файл состояния;
* отправка учётных данных куда-либо кроме `globus.ru`;
* инъекция в параметры запросов через аргументы инструментов;
* попадание чужих персональных данных в вывод инструментов.

## Что уязвимостью проекта не является

* уязвимости самого сайта `globus.ru` — сообщайте о них владельцу сайта, не сюда;
* изменение или отключение внутреннего API ГЛОБУС;
* недоступность сайта с зарубежного IP.

## Модель угроз для пользователя

Сервер хранит состояние сессии в `~/.globus-mcp/state.json` (права `600`):

| Поле | Содержимое | Риск |
|---|---|---|
| `app_id` | UUID устройства | к нему привязана корзина |
| `phone` | телефон последнего входа | персональные данные |
| `token` | **JWT в открытом виде** | полный доступ к аккаунту на срок жизни токена |

Практические выводы:

* файл не коммитить, не прикладывать к issue, не класть в общие каталоги;
* `auth_logout()` стирает токен, удаление файла даёт новую анонимную сессию;
* каталог переопределяется переменной `GLOBUS_MCP_HOME`;
* токен живёт около часа, но до истечения даёт доступ к аккаунту;
* `checkout_info()` возвращает имя, телефон и адреса — эти данные попадут
  в контекст языковой модели и, возможно, к её провайдеру;
* инструменты корзины изменяют **реальную корзину** аккаунта. Оформление заказа
  и оплата не реализованы, потратить деньги сервер не может.
