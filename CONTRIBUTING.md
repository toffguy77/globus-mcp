# Как участвовать

Спасибо за интерес к проекту. Здесь коротко о том, как устроена работа.

## Главное правило

**Ветка `main` защищена: прямой push запрещён всем, включая владельца репозитория.**
Любое изменение попадает в `main` только через pull request с зелёным CI.

## Быстрый старт

```bash
git clone https://github.com/toffguy77/globus-mcp.git
cd globus-mcp
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
pytest && ruff check .
```

## Рабочий цикл

1. Форкните репозиторий (или создайте ветку, если у вас есть права на запись).
2. Ветка от `main` с осмысленным именем: `fix/build-id-404`, `feat/favorites`.
3. Небольшие связные коммиты. Заголовок в повелительном наклонении, до 72 символов:
   `добавь ретрай на протухший buildId`.
4. `pytest` и `ruff check .` — зелёные локально.
5. Откройте pull request, заполните шаблон.
6. CI прогоняет тесты на Python 3.10–3.13 и линтер. Красный CI мержить нельзя.

Апрув ревьюера не требуется — проект ведёт один мейнтейнер. Но PR обязателен:
он даёт историю изменений, прогон CI и место для обсуждения.

## Что нужно проверить перед PR

* `pytest` — все тесты офлайн, ни один не ходит в сеть и не трогает `~/.globus-mcp`.
  Новый код должен сохранять это свойство: подменяйте транспорт `httpx.MockTransport`
  (см. фикстуру `fake_client` в `tests/conftest.py`).
* `ruff check .` — без замечаний.
* Меняли запросы к API — обновите [docs/API.md](docs/API.md) в том же PR.
* Добавили или переименовали инструмент — обновите таблицу в `README.md`.

## Стиль

* Код, докстринги, комментарии, README и сообщения коммитов — **на русском**.
  Докстринги инструментов видит LLM-клиент: пишите в них формат аргументов
  и откуда их взять.
* Длина строки — 100 символов, следит `ruff` (конфиг в `pyproject.toml`).
* Разделение слоёв: `client.py` — только транспорт и состояние, `server.py` —
  инструменты и нормализация ответов. Форматирование в клиент не переносим.
* Единое представление товара — функция `brief()`. Меняете вид товара в выдаче —
  меняйте её, а не отдельные инструменты.
* Цены в API приходят в копейках. Любое новое поле с ценой оборачивайте в `rub()`.

## Что не принимается

* **Оформление заказа и оплата.** Решение осознанное: сервер не должен уметь
  тратить деньги пользователя.
* Обход блокировок, антибот-защиты или ограничений сайта.
* Нагрузочные сценарии, массовый парсинг каталога, что угодно, что создаёт
  ненужную нагрузку на чужой сервер.

## Сообщения об ошибках

Заведите [issue](https://github.com/toffguy77/globus-mcp/issues) по шаблону.
Приложите версию Python, версию пакета `mcp`, вызов инструмента и текст ошибки.

**Никогда не прикладывайте содержимое `~/.globus-mcp/state.json`** — там ваш JWT.
Уязвимости присылайте не в issue, а по адресу из [SECURITY.md](SECURITY.md).

Учтите: сайт закрыт для зарубежных IP. Ошибка соединения из-за рубежа — не баг.
